Windows 上 curl 怎么走 Clash？先核对混合代理端口

小宇2026-11-14— 次阅读
客户端教程

浏览器能打开网页，PowerShell 里的 curl 请求却一直超时。用 Windows 版 Clash Verge Rev 时，可以先让这一条命令明确连接 Clash 的本机代理端口，再检查请求有没有送到。这也适合排查下载脚本，尤其是你暂时只想测试一条请求的时候。

curl 是一个在命令行里请求网页或下载文件的工具。本文在 PowerShell 中写成 curl.exe，直接调用 curl 程序。以下以无需登录的公开示例网站为目标，演示如何设置和读结果。资料核对日期为 2026 年 11 月 14 日。

先找 Clash 实际在用的端口

打开 Clash Verge Rev，在首页的「Clash 信息」或设置里的端口配置中找「混合代理端口」。端口可以理解为同一台电脑上某个程序接收请求的入口号码。混合端口能接收 HTTP 代理和 SOCKS5 代理两种方式的请求，下面用 HTTP 代理。照着软件当时显示的号码填，示例中的 7897 只是演示，换过配置后也值得再看一眼。Clash Verge Rev 界面标签 · Mihomo 代理端口说明

地址里的 127.0.0.1 指当前运行命令的这台电脑。如果命令是在另一台电脑或远程终端运行，先回到运行 Clash 的 Windows 电脑上做这个例子。

给一条命令指定代理

确认 Clash 正在运行，然后在 PowerShell 中执行下面这行。把 7897 换成你看到的混合代理端口。

curl.exe -q --proxy "http://127.0.0.1:7897" --max-time 15 --verbose --output NUL "https://example.com/"

--proxy 指定 curl 先连哪一个代理。这里前面的 http:// 对应本机 HTTP 代理，末尾的 https://example.com/ 是要访问的网站。-q 放在最前面，让 curl 跳过自己的默认配置文件，--max-time 15 限制这次等待的时间，--verbose 显示连接细节，--output NUL 把网页正文丢弃，方便看连接输出。这次传入的参数随命令执行，用于单次请求。排查时可以先用公开网页，详细输出可能包含请求头。curl 命令手册

从输出里看请求走到哪一步

先看有没有连上 127.0.0.1 和你填的端口。假如报连接被拒绝，可以检查 Clash 是否仍在运行、混合端口的号码是否填对。也可以单独用 Windows 的端口检查命令。把号码同样替换成你自己的。

Test-NetConnection -ComputerName 127.0.0.1 -Port 7897

看到 TcpTestSucceeded 为 True，说明这次可以连到该端口。接下来仍需要用 curl 验证代理能否处理请求。如果详细输出直接显示它在尝试连接网站地址，再检查命令里有没有写 --proxy，以及 NO_PROXY 是否包含测试网站。NO_PROXY 是一份告诉 curl 哪些站点要绕过代理的设置。Microsoft 端口测试说明 · curl 的代理绕过选项

已交给 Clash，再查最终走的路线

连上混合端口以后，可以在 Clash 的连接或日志里按时间找这次访问的域名。启用规则模式时，规则会决定这个网站走某个节点还是直连。假如请求在本机端口就失败，先解决端口问题。假如代理已接到请求，浏览仍失败，再看被选中的路线和目标网站的响应。比较两次时，用同一个网址，每次只改一个配置。Clash Verge Rev 的模式说明

访问 HTTPS 网页时，详细输出里可能先出现一条 CONNECT，它是 curl 请代理建立通往网站的连接。如果紧接着看到 200 Connection established，表示代理接受了这项请求。继续往下看，网站自己的 HTTP 状态码会在后面出现。比如随后收到 404，可以先核对网页路径。如果在网站返回状态前就停在证书错误，则保留完整的错误文字，先核对系统时间和访问的域名。curl 的代理连接说明

举个例子，若这条命令已经收到示例网站的正常响应，换成原来下载出错的网址后才失败，可以记下两个网址、测试时间、Clash 选的路线和最后出现的错误。下次遇到同样的问题，从这几项开始对比，容易看出变化出在本机设置还是某个目标网站。

如果两次都是用同一个代理端口，可以先固定端口，只在 Clash 里换一个节点，再访问原网址。每轮记下最后一条状态码或错误，判断依据会比单看浏览器能否打开更清楚。需要在另一台电脑重做测试时，先从那台电脑上的 Clash 界面重新核对端口。
